# Inf-Dir 对照 Files 功能路线图

本文记录 Inf-Dir 与 Files 的功能差距、优先级和验收标准。它用于规划后续
迭代，不要求机械复刻 Files；Inf-Dir 仍以 i3 动态分割、多 workspace 和
独立进程 Viewer 插件体系为核心差异。

## 1. 对照基线

- Files 参考源码：`ai_refs/files`
- Files commit：`c4a4ff95b413b8ea3d0f04fc13ef99512bf135cc`
- 基线日期：2026-07-21
- Inf-Dir 基线：`cb52349`

更新 Files submodule 后，应先更新本节 commit，再重新核对新增功能，避免
路线图随上游变化失去可复现性。

## 2. 已有能力

以下能力已经存在，不属于本路线图的待办范围：

- i3 风格任意水平/垂直分割、关闭、缩放、面板交换和多 workspace；
- 每面板独立路径、标签页、历史、排序、分组、过滤和视图模式；
- 文件与正文搜索（fd/ripgrep 插件）；
- manifest 驱动的独立进程 Quick View Viewer；
- 新建、复制、剪切、粘贴、移动、删除、重命名和创建快捷方式；
- Windows Shell 右键菜单、打开方式、属性和 Shell New 集成；
- Home、最近文件、收藏、快速访问、驱动器和回收站浏览；
- CfAPI 云盘发现与同步状态显示；
- 明暗主题、隐藏文件和文件扩展名开关。

## 3. 规划原则

1. 先修复可见但无响应的命令，再增加新入口。
2. 先补齐文件操作的可靠性，再扩展 Git、标签等增强能力。
3. Windows Shell 能力可以作为 fallback，但核心工作流应有一致的应用内入口。
4. 长耗时文件操作不得阻塞 Flutter UI isolate。
5. 文件系统与 Shell 集成继续使用 Win32 / COM / Shell FFI，不引入主进程第三方 DLL。
6. 新 UI 必须使用 `app_theme.dart` token，并同时覆盖明暗主题。
7. 每项功能完成时必须包含失败路径、取消/重入行为和相应测试。

## 4. P0：产品完整性与可靠性

### 4.1 清理无响应菜单

当前 `file_pane.dart` 中以下命令传入了空回调，用户可以点击但没有结果：

- [x] 实现“在新窗口中打开”，或在多窗口功能完成前隐藏该菜单项。
- [x] 实现“发送到”，或先隐藏该菜单项。
- [x] 实现“固定到侧边栏”，并提供对应的取消固定入口；或先隐藏该菜单项。
- [x] 检查全部菜单，禁止以非空 callback 表示未实现功能。
- [x] 为菜单 enable/visible 状态增加 FilePane widget 集成测试（本轮已补 builder 单测）。

验收标准：界面中不存在点击后无反馈、无动作的命令。

### 4.2 补齐应用菜单

顶部“文件、编辑、收藏夹、信息”目前只是占位标签。

- [ ] 文件菜单：新建标签页、新建窗口、关闭标签页、关闭面板、退出。
- [ ] 编辑菜单：Undo、Redo、剪切、复制、粘贴、全选、反选。
- [ ] 收藏夹菜单：添加收藏、移除收藏、管理收藏。
- [ ] 信息菜单：关于、版本、日志位置和问题反馈入口。
- [ ] 所有菜单命令复用统一 Action/Command，不复制 FilePane 业务逻辑。
- [ ] 命令可用性随焦点面板、选择项和剪贴板状态更新。

### 4.3 回收站完整工作流

目前只能枚举回收站，应用主动禁用了项目打开行为。

- [x] 恢复选中项目到原始位置。
- [x] 原始位置不存在时提供明确处理方式（选择其他位置或还原到桌面）。
- [x] 原始位置同名冲突时提供明确处理方式（替换 / 保留两者 / 跳过）。
- [x] 全部恢复。
- [x] 永久删除选中项目。
- [x] 清空回收站，并显示不可撤销确认。
- [x] 操作完成后刷新回收站面板和已打开的原始目录。
- [ ] 覆盖取消、失败、空回收站和多选测试（已补还原目标规划与冲突检测单测，对话框与原生交互待覆盖）。

验收标准：用户不需要打开 Explorer 即可完成常见回收站操作。

### 4.4 文件任务中心

当前复制、移动和删除使用静默 `IFileOperation`，没有进度、取消、冲突处理
和失败明细；同步 FFI 还可能阻塞 UI isolate。

- [ ] 建立统一 `FileOperationTask` 模型：类型、来源、目标、状态和结果。
- [ ] 原生层通过 `IFileOperationProgressSink` 或等效机制报告进度。
- [ ] 文件操作移出 UI isolate，Flutter 侧只消费任务事件。
- [ ] 提供任务中心：排队、进行中、成功、失败和已取消。
- [ ] 支持取消尚未完成的任务。
- [ ] 支持同名冲突：替换、跳过、保留两者，并可应用到全部。
- [ ] 展示可定位到具体路径的失败原因。
- [ ] 操作完成后只增量刷新受影响的面板和目录 cache。
- [ ] 应用关闭时处理进行中任务，禁止静默中断。

验收标准：大文件、跨盘和批量操作期间 UI 保持响应，用户可以看到结果并
处理冲突。

### 4.5 Undo / Redo

底层设置了 `FOF_ALLOWUNDO`，但应用没有可操作的历史栈。

- [ ] 定义应用级文件操作历史及可撤销边界。
- [ ] 支持复制、移动、重命名、新建和回收站删除的 Undo。
- [ ] 支持 Redo，并在新操作后正确截断 redo 栈。
- [ ] 接入 `Ctrl+Z`、`Ctrl+Y` 和编辑菜单。
- [ ] 不可撤销操作必须在执行前明确提示。
- [ ] 撤销后同步更新所有展示相关路径的面板。

### 4.6 文件拖放

- [ ] 面板内拖动文件到文件夹。
- [ ] 跨面板复制/移动，按 Windows 修饰键规则决定操作类型。
- [ ] 拖到标签页、侧边栏目录和 workspace 面板。
- [ ] 接收 Explorer 等外部进程拖入的文件。
- [ ] 将文件拖出到 Explorer 或其他支持 CF_HDROP 的应用。
- [ ] 显示合法目标、拒绝目标和复制/移动意图反馈。
- [ ] 防止拖到自身、后代目录或只读/虚拟位置。

### 4.7 接通详情与预览面板

`PaneController` 和会话快照已有 `showDetailsPane`、`showPreviewPane` 状态，
但没有实际 UI。

- [ ] 增加详情面板入口并渲染名称、类型、大小、时间、路径等元数据。
- [ ] 多选时显示选择数量与总大小。
- [ ] 增加预览面板入口，并复用 Quick View 插件解析规则。
- [ ] 详情与预览互斥逻辑与现有 Controller 状态一致。
- [ ] 面板可调整宽度，且每个 pane 独立保存状态。
- [ ] 无选择、不支持预览、加载中和 Viewer 失败均有明确状态。

## 7. 推荐实施顺序

依赖关系如下：

```text
占位命令清理
    |
    +--> 回收站工作流
    |
    +--> 文件任务中心 --> Undo/Redo --> 文件拖放
    |
    +--> 详情/预览面板 --> 缩略图
    |
    +--> 多窗口 --> 高级标签页
    |
    +--> 设置中心 --> 网络/缩略图/文件夹大小偏好
```

建议里程碑：

1. M1 完整性：清理空回调、补顶部菜单、完成回收站。
2. M2 操作可靠性：文件任务中心、冲突处理、Undo/Redo、拖放。
3. M3 浏览体验：详情/预览、缩略图、压缩与解压。
4. M4 导航能力：多窗口、高级标签页、网络位置和设置中心。
5. M5 增强生态：标签、分享、Git 和自定义命令。

## 8. 通用完成标准

每个复选项只有同时满足以下条件才可标记完成：

- 功能入口、成功路径、失败路径和取消路径完整；
- 不阻塞 UI isolate，不造成窗口无响应；
- 多 pane、多 workspace 和多标签场景行为一致；
- 文件变更后目录 cache、选择状态和侧边栏正确同步；
- 支持路径空格、Unicode、长路径、只读目录和权限错误；
- 明暗主题、键盘操作和高 DPI 下无布局问题；
- Dart 单元/widget 测试与必要的 Windows 原生测试通过；
- `flutter analyze` 和 `flutter test` 通过；
- 相关架构或协议变化同步更新 `docs/`。
